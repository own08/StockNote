# Stock Note — PC・スマホ対応の週次在庫管理

化粧品・シャンプー類の在庫と発注を管理する、日本語の個人用ブラウザアプリです。GitHub Pages + SupabaseでPC・スマホの同じデータを扱えます。外部JavaScriptライブラリやビルド作業は不要です。

## クラウド版の初期設定

**[SETUP.md](SETUP.md)** に沿って、Supabaseの作成・ログイン設定・GitHub Pages公開・既存データ移行を行ってください。`config.js` はクラウドモードですが、接続情報は未入力です。初期設定を終えるまでは同期できません。

クラウドモードは在庫・発注・週次履歴・マスタ・商品の手動順を同期します。PCは表、スマホはカードで表示します。現在の端末の未送信データはタブ内に保護し、同時更新を検知した場合は古い内容で上書きしません。

以下の「起動」「保存先」の説明は `config.js` で `mode: 'local'` にした**ローカルモード**向けです。クラウドモードではSupabaseにデータを保存します。

## 起動

1. ZIPを展開してください。
2. `stock-note` フォルダの `index.html` をダブルクリックし、Chrome / Edge / Firefox / Safari の新しいバージョンで開きます。
3. 「ブランド・用途」でブランドを追加し、「＋ 商品を登録」で使い始めます。

HTML・CSS・JavaScript（app.js / config.js / cloud.js）は同じフォルダに置いてください。インターネット接続は不要です。

### ローカルHTTPサーバーで開く場合

Python 3がある環境では、ターミナルで `stock-note` フォルダへ移動して実行します。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザで http://127.0.0.1:8000 を開きます。終了はターミナルで Ctrl+C。

ダブルクリック起動で保存が制限されるブラウザでは、この方法を使ってください。起動方法・ブラウザ・プロファイル・フォルダの場所・ポートを変えると、別の保存領域になる場合があります。切り替える前にJSONバックアップを保存し、切り替え先で復元してください。

## 毎週の使い方

- **在庫一覧**で日付を選びます。選んだ日の月曜日を週の開始日として扱います。未来週は入力できません。
- 「選択週の記録」の数値欄に在庫数を入力し、Enterまたは枠の外をクリックすると自動保存します。空欄は未記録、0は在庫ゼロです。
- 「現在庫を記録」で現在庫数を選択週へ転記できます。既存記録があれば確認後に更新します。
- **今週**の週次数を保存すると現在庫も更新します。**過去週**の保存は履歴だけを更新し、現在庫は変えません。
- 週が変わっても自動で記録を複製しません。記録はその週の確認値として残ります。
- 「推移」で週次グラフと履歴テーブルを確認できます。グラフは記録がある週を等間隔で表示します。
- 現在庫が発注点以下（等しい場合を含む）の商品は「要発注」と表示します。適正在庫は目安です。
- 商品名検索、ブランド・用途・在庫状態フィルタ、商品名・現在庫・ブランドでの並べ替えができます。警告とフィルタは選択週でなく**現在庫**を使います。

## 発注・入荷

1. 商品行の「発注」、または「発注済み」タブの「＋ 発注を登録」で作成します。
2. 既存商品を選ぶと商品名・ブランド・用途を引き継ぎます。在庫未登録の商品も発注できます。
3. 「入荷・在庫へ」で今回の入荷数を入力します。チェックが入っていると現在庫へ加算します。
4. 一部だけなら「一部入荷」、全量処理で「入荷済み」になります。発注残数を超える処理はできません。
5. 在庫にない商品は、ブランド・用途・メモを引き継いで新規登録します。数量0なら商品情報だけを引き継げます。新規商品の発注点・適正在庫は0なので、在庫一覧で編集してください。

**ステータスを編集しただけでは在庫は増えません。**「入荷・在庫へ」で処理してください。入荷数を記録して加算チェックを外した場合も、処理済み数量に含まれ、あとから同じ入荷数を再加算できません。必要な訂正は商品編集の現在庫で行ってください。発注自体を削除しても加算済み在庫は戻りません。

入荷加算と商品編集は、過去の確認値を保つため週次履歴を書き換えません。入荷後の数量を今週の記録にしたい場合は、在庫一覧で再記録してください。週次記録は棚卸し値であり、入出庫の取引台帳ではありません。

## ブランド・用途の管理

用途はボディ・フェイス・ヘッドを初期登録済みで、複数選択できます。ブランドと用途は追加・名前変更が可能です。名前変更は商品と発注に反映します。使用中のマスタ項目は削除できません。

## 保存とバックアップ

保存先は、このブラウザのlocalStorage（キー：`stock-note-v1`）です。アプリのフォルダ内にはデータファイルを自動生成しません。プライベートブラウズやブラウザデータ削除ではデータが失われることがあります。週次確認後にJSONバックアップを保存する運用をおすすめします。

- **JSON**：商品・発注・履歴・マスタ全体を保存します。復元は検証と確認後に全体を置換します。
- **CSV**：在庫商品・発注・週次履歴を個別に出力・取り込みできます。UTF-8 BOM付き、改行やカンマを含む値にも対応します。
- CSVは同じIDを更新、新しいIDを追加します。商品・発注のID空欄は新規IDを作ります。重複する商品名は自動統合しません。履歴は商品IDと週で更新します。
- CSVの取り込みで不足するブランド・用途は追加します。商品IDの参照先が存在しない発注・履歴、負数・小数、不正日付などは取り込まず、既存データを保持します。
- 別環境へのCSV移行順は在庫商品 → 発注 → 週次履歴。マスタを含めた完全移行にはJSONを使ってください。
- 履歴CSVの取り込みは現在庫を変更しません。現在庫は商品CSVの `stock` で管理します。
- 表計算ソフトの数式として扱われやすい先頭文字には出力時に `'` を付け、本アプリでの取り込み時に戻します。

### CSV列（英語の列名・順序を維持）

在庫商品：`id,name,brand,tags,stock,point,target,note`

発注：`id,productId,name,brand,tags,qty,date,due,status,received,note`

週次履歴：`productId,week,qty`

`tags` は `["ボディ","フェイス"]` のようなJSON配列です。CSV上の引用符は二重化されます。日付は `YYYY-MM-DD`、履歴の週は月曜日。数量は0以上の整数（発注数のみ1以上）。`received` は在庫加算の有無を問わない処理済み数です。ステータスは「発注済み」「一部入荷」「入荷済み」「キャンセル」。空のCSVも出力できるので、テンプレートとして使えます。

## サンプル

「データ管理」から、商品・発注・履歴が空の場合のみ架空の商品3件と4週間分の履歴を追加できます。サンプルは自動では入りません。

## 制約・検証

- 同時編集を避け、基本的に1つのタブで利用してください。別タブの保存変更は反映しますが、複数人の共同編集向けではありません。
- 保存に失敗した場合は警告し、保存成功として扱いません。破損した保存データは自動上書きせず、JSON復元まで保存を止めます。
- 自動バックアップ、通知、発注送信機能はありません。クラウド同期はクラウドモードのみ対応します。
- JavaScript構文チェックおよび、CSV往復、日付・数量・参照検証、過去週と今週の保存、同一週の更新、一部／全量入荷、二重加算防止のロジック検証を実施済みです。実ブラウザでの操作・表示確認は未実施です。

## 商品の順番を変更する

在庫一覧の並べ替えで「手動の並び順」（初期表示）を選び、各商品の左側の ↑ ↓ を押してください。順番は自動保存され、次回起動時にも維持されます。新規商品は末尾に追加されます。

検索・絞り込み中は、表示されている前後の商品と位置を交換します。非表示の商品はその位置を維持します。商品名順などへ切り替えても保存した順番は変わらず、「手動の並び順」で戻せます。

JSONバックアップ・復元は順番も保存します。CSV出力も手動順になりますが、CSV取り込みで既存商品の順番は変更しません。

更新時は念のためJSONバックアップを保存し、元のフォルダのHTML・CSS・JavaScriptを新しいファイルで置き換えてください。同じブラウザ・同じ場所で開くと既存の保存データを引き続き使用します。

## 同期版の検証状況

従来の在庫ロジックに加え、API応答を模擬した2端末の保存競合、通信応答の消失と再試行（重複保存なし）、オフライン時の未送信保護、最新版取得、ログアウトを検証しています。Supabaseの実プロジェクトはまだ接続されていないため、実サービス上での認証・RLS・端末間同期は初期設定後の確認が必要です。
